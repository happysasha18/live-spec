# Method finding: a human verdict on shown work is a movement end — it lands in resume files the same minute

From: the tlvphotos window, 2026-08-08. Root: Alexander's question 16:57 («это инструкция не
соблюдена или как?») after an adversarial review caught the gap; his word sanctions notifying
live-spec (17:03).

**What happened.** A prototype batch was built and the resume files (NEXT_STEPS anchor, project
charter) correctly said «awaits his walk». His rejection then arrived MID-CONVERSATION; the
session dove into the design dialogue the rejection triggered and spent two hours committing
design updates — while the resume files still said the walk had not happened. A context wipe in
that window would have made the next session rebuild the rejected artifact by written
instruction. An adversarial clean-context reviewer caught it; neither the session nor the human
did.

**The method gap.** The movement-end rule (update NEXT_STEPS + report after a big movement)
binds at movement ends — and a verdict arriving mid-conversation does not FEEL like a movement
end, because the conversation continues. But for the artifact judged, the movement ended at the
verdict. Chat does not survive a context wipe; only files do.

**Proposed rule for the pack (base rules / build-pipeline showing step):** a human verdict on
shown work — approval or rejection — is a movement end for the judged artifact, and it is
written into the resume files (queue row, charter/STATE line) in the same minute it lands,
before the conversation it triggers continues. Corollary for documents: a new verdict amends
the superseded line IN PLACE and the old text moves to history; appending addenda over stale
text is the failure mode that produced this incident.

**Local fixes already made in tlvphotos** (working example): the amend rule at the top of
lab/CROSSING-BRIEF.md; a personal memory entry; the stale anchor corrected.
