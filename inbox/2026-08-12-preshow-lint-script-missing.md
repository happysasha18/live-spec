# Показ артефакта заблокирован законом, чей инструмент в проекте не установлен

От: окно tlvphotos, 12.08.2026 18:20. Корень: закон сессии №3 — перед показом артефакта прогнать
`python3 scripts/preshow-register-lint.py <path>` из корня проекта, и ненулевой выход показ блокирует.

**Что случилось.** Сегодня в tlvphotos страница плана готовилась к показу владельцу. Файла
`scripts/preshow-register-lint.py` в проекте нет: ни в рабочей папке, ни на других ветках, ни в
истории (`git log --all --diff-filter=A` пусто). Того же нет и у `guardrails/spec-coinages.json`,
который закон №2 называет списком запрещённых слов для сверки перед письмом. Оба пути называются в
правилах сессии как существующие.

**Как обошли.** Проверку сделали руками: развёрнутый поиск по видимому тексту страницы на известные
внутренние слова, с разбором каждого совпадения по месту. Все найденные следы сидели внутри записи,
которая цитирует их как то, чего владелец не смог прочитать, — законная историческая цитата. Показ
состоялся.

**Почему это дефект пакета, а не проекта.** Закон обязателен и не выводим из подручного: механическая
проверка на месте была бы зелёной по причине отсутствия, и любое окно с этим законом либо остановит
показ навсегда, либо тихо пройдёт мимо гейта. Проверка, которую нельзя запустить, — это гейт,
который никогда не краснеет.

**Что просим.** Либо положить оба файла в устанавливаемую часть пакета, чтобы новый проект получал их
при подключении, либо переписать законы 2 и 3 так, чтобы они называли своё поведение при отсутствии
инструмента и не выдавали несуществующий путь за существующий.
