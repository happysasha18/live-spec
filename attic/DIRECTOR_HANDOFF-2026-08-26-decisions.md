## Решения
- Владелец подтвердил: пушить в GitHub без спроса разрешено.
- Владелец потребовал: не пропускать реальный skill-creator eval/iterate цикл (не ручной разбор).
- Мандат: резать прозу только по измерению, не по числовому лимиту. Честный отказ резать — нормальный итог. Не записывать числа "про запас" без кода/теста, который их читает.
- Версия скилла не своя — одна версия на весь пакет (`VERSION`; INV-178).
- 10 правил-кандидатов на новый гейт (Полоса A) — решение владельца, не начинать без спроса.

## Ловушки среды
- Push из bare-репозитория ломает gate a. Обход (не `--no-verify`):
  `cd /private/tmp/ls-director/wt && GIT_DIR="$(git rev-parse --git-dir)" GIT_WORK_TREE="$(pwd)" git push origin <branch>:main`
- Полный `pytest` локально часто виснет на 0% CPU. Не гонять без присмотра — полный прогон только на CI.
- `tests/test_guardrails.py` делает `git stash`, не восстанавливает при обрыве. Коммитить до прогона, гонять точечно.
- Правка `guardrails/pre-push` требует `guardrails/install.sh` после. Правка `skills/*/SKILL.md` требует `scripts/sync-skills.sh` после, при каждой повторной правке заново — иначе gate m красный.
- Pin-реестры (`.live-spec/r*-rule-*.md`, `architecture/*.md`) сдвигаются при вставке/удалении строк в SKILL.md — проверять gate g.
- Prover- и skill-review-записи коммитятся отдельными коммитами.
- `tiktoken` стоит в системном `python3` — держать, полезен для измерений токенов.
