Findings: (1) THE FAULT, named directly rather than euphemised: gate af (built and shipped in this same branch's prior range, `de5158b8`/`22dcaba7`) reworded seven gates.yml step names to match pre-push's law sentences byte-for-byte, and one of those seven — gate a's — carries a colon followed by a space ("one record per push: the re-check of the spec and the architecture..."). A YAML `- name: <value>` line is a mapping whose value is a plain scalar, and an unquoted colon-space inside that scalar is read as the START OF A NESTED MAPPING, not as a character of the string — the file stopped parsing at that exact byte, and GitHub's own workflow runner refused to even start the job ("This run likely failed because of a workflow file issue"). Gate af's own text-equality check ran entirely inside Python, reading gates.yml as a plain string with a regex — it verified the LAW SENTENCE was byte-correct and never asked, at any point, whether the FILE it had just rewritten still parsed as the format it is. Locally green; on the server, the job never ran, so no CI check — including gate af's own mirrored CI step — ever got the chance to catch its own damage. Two already-reviewed, already-pushed packages (`07cf715d`, `3447b667`) went red through no fault of their own content, purely because the shared workflow file beneath them had stopped being a file. (2) The design choice, and why: quote every step name (all 27 in the file, not only the 24 gate af holds to text equality) rather than move the law sentence out of the `name:` field into a comment or a separate key read by a custom parser. Quoting is the smaller, standard fix for the actual defect (an unescaped YAML special character inside a scalar) and it keeps the design's whole point intact — the step name still IS the canonical law, verbatim, readable as such by a human scanning the Actions UI, rather than splitting the law across a terse name and a buried comment that could itself drift unguarded. The alternative (restructure away from `name:`) would have re-opened exactly the multi-copy-of-one-law problem this whole gate exists to close. (3) Verified this was not a narrower typo: grepped all 27 step-name lines (`grep -n "^      - name:"`) for a second unquoted colon-space, a trailing colon, or a leading YAML-special character (`*&!|>%@\`'"`) on any of them — gate a's was the only offender in the committed file before this fix; the other 23 mirrored law sentences and the 3 unmirrored step names (install steps, the suite step) carry no such character. All 27 are now quoted uniformly regardless, so a future gate whose law happens to contain a colon, a leading `*`, or any other YAML-special character cannot reopen this hole by accident — the fix closes the class, not the one instance.
