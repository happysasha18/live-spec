## What changed

This is a plan-mandated pack-wide skill-creator pass ahead of a release step, run one skill at a
time. For `director`, it specifically closes push gate s: `director`'s last substantive change,
commit `5db30805` ("Director: define decision, grounds, halt and correction"), had no skill-review
record covering it. `git show --stat 5db30805` confirms its actual footprint — `skills/director/
SKILL.md` (+21/−3) and `architecture/pipeline-and-lanes.md` (+1/−1, a line-pin correction for the
insertion) — nothing under `references/`. The commit adds four short definitions (decision,
grounds stated with an act, halt, correction) beside the acts table and the highlighted-rules block
they belong to, closing four gaps PLAN.md step 2 named by grepping for each term's absence first.
This record is that missing skill-review; nothing in `skills/director/` was edited to produce it.

## Findings

**Read fresh** — `skills/director/SKILL.md` whole (340 lines, `wc -l` confirmed), then every file
under `skills/director/references/` (13 files, `delegation-protocol.md` through `work-kind-table.md`),
cross-checked against every `skills/*/SKILL.md` in the pack via `grep -rln "director/references"`.

1. **Frontmatter description — accurate, not literally "pushy."** The description states both WHAT
   (read the human's message, classify the act, work only accepted work) and, loosely, WHEN (before
   anything acts on it) — it matches the body exactly: the seven-acts table, the "only for work that
   was actually accepted" gate, and the checkpoint/verify/close/report Execution chain are all there
   as described. It does not carry explicit trigger phrases the way a general-audience skill would
   ("use this when the user says..."). That is not a defect here: `CLAUDE.md` hard-routes every
   request through director ("The door for any request is the director skill") rather than relying
   on natural-language description-matching, so the pushiness Anthropic's guide asks for is supplied
   by the pack's own routing layer, not this field. Non-blocking observation, not a finding.

2. **Anatomy of a Skill — solid for the file's actual role.** The body opens with the two questions
   director exists to keep apart, then walks them in order (`## First — what did the human just
   do?`, `## Then... what does it touch?`, `## The decision sheet`, `## Execution`) — clear top-level
   decision logic, exactly what a first-reader-of-every-message skill needs at the top. Detail that
   would bloat the main read is pushed out: build order to `references/build-craft.md`, the bug-class
   sweep to `references/class-hunt.md`, landing mechanics to `references/landing-law.md`, the verifier
   protocol to `references/verify-step-detail.md`. These four links are real — each target file's own
   header confirms the same pointer back (`build-craft.md`: "referenced from SKILL.md's specialist
   table, the Developer row"; matching headers in the other three). This part of the skill is
   correctly built.

3. **Progressive Disclosure by size — clean.** `SKILL.md` is 340 lines, well under the ~500-line
   guide. Every `references/` file is well under 300 lines (largest is `delegation-protocol.md` at
   110); none needs a table of contents.

4. **Lack of Surprise — the commit itself is clean; the standing reference set is not.** Nothing in
   `5db30805`'s diff is malicious or misleading, and the four new definitions match the surrounding
   table's register exactly. But a reader who explores `references/` independently (as this review
   did, and as any future session might via `ls` or grep) meets files whose own opening line makes a
   false claim. See the reference-file-consistency finding below — same root cause, this is where it
   bites the surprise principle.

5. **Writing style — consistent with the file's established register**, already reviewed adversarially
   across three prior passes (2026-08-21, 2026-08-24, 2026-08-25) with no style objections raised and
   none found now: imperative mood, WHY given before rules ("Running them together is what turns a
   question into a ticket"), worked examples used where a table alone would not carry the judgment
   (the "sheet at the size the work deserves" example). No new stylistic issue in the reviewed diff.

6. **Reference-file consistency — a real, non-blocking finding, not caused by this commit.**
   `SKILL.md`'s body links exactly four files under `references/`: `build-craft.md`, `class-hunt.md`,
   `landing-law.md`, `verify-step-detail.md`. The other nine files in that directory —
   `delegation-protocol.md`, `drafter-applier-example.md`, `excuses-table.md`, `footprint-read.md`,
   `guardrails-catalog.md`, `lanes-and-pen.md`, `mockup-first-entry.md`, `request-kind-table.md`,
   `work-kind-table.md` — are not linked from `SKILL.md` anywhere. Each of eight of them opens with a
   sentence naming exactly which section of `SKILL.md` supposedly points to it: "Gates worth
   remembering," "Guardrails — the pipeline's mechanical enforcement," "The work-kind table," "When to
   run it," or an "intake line." `grep -n "^#\|^##" skills/director/SKILL.md` lists the file's actual
   eleven headings — none of those four section names appears, and a text search for "work-kind,"
   "work kind," and "door" (the vocabulary `footprint-read.md` and `mockup-first-entry.md` still use
   for the entry-classification system they document) turns up nothing comparable in the current body
   either. `git log --oneline -- skills/director/SKILL.md` places the removal of that older
   door/work-kind section structure at `ad851b7d` ("shadow mode ends, the skill acts," 2026-08-24) —
   two days before `5db30805` — when the file was rewritten onto the current acts/dimensions model.
   The eight files were never removed, folded, or re-pointed at that rewrite, and three director
   reviews since (`2026-08-24-director-acting.md`, `2026-08-25-director-redesign-gaps.md`,
   `2026-08-26-build-pipeline-director-orphan-cleanup.md`) did not catch it — the closest miss is the
   08-26 orphan-cleanup record, which fixed a dead relative link from `lanes-and-pen.md` to
   `drafter-applier-example.md` inside this same cluster without noticing that `lanes-and-pen.md`
   itself is unreachable from `SKILL.md`. A ninth file, `work-kind-table.md`, is not a pure orphan —
   `skills/live-spec-base/SKILL.md` line 240 still points to it by path as "the per-kind table's one
   home" — but it is still unreachable from `director/SKILL.md`'s own body, despite that body's own
   opening claim that "loaded alone, every section below still runs."

This finding does not touch `5db30805`'s diff (`git show --stat` above shows no `references/`
change in that commit) and predates it by two days, so it does not block closing gate s for this
commit. It is real pack-hygiene debt worth its own cleanup pass, the same shape as the fix
`2026-08-26-build-pipeline-director-orphan-cleanup.md` already made for two files in this same
cluster — this review found six more the earlier pass did not reach, plus the fact that the file
it did move (`drafter-applier-example.md`) is still only reachable through the still-orphaned
`lanes-and-pen.md`.
