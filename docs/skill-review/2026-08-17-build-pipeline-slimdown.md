# `SKILL-REVIEW` — build-pipeline, five sections leave the body and one pointer breaks on the way out

Skill: build-pipeline. Date: 2026-08-17. Range: 9efe559..HEAD.

Commits of the range touching `skills/build-pipeline/`:

    88c4622 build-pipeline: five reference sections move out of the body, word for word, and the tests read the whole surface

Verdict: ALLOW WITH FINDINGS. The word-for-word claim is true — every moved passage survives byte-identical modulo indentation, and nothing was silently dropped — but the move carried a relative link across a directory boundary without re-basing it, so `references/drafter-applier-example.md` is now unreachable from anywhere in the skill; two of the cuts took a gate's firing condition and a named test's questions out of the body; and `references/delegation-protocol.md` now states the same six invariants twice inside one file.

## What changed

`SKILL.md` fell from 672 lines / 64,143 bytes to 559 lines / 52,432 bytes. Five passages left the body into new files — the footprint read at intake, the mockup-first entry condition at intake, three passages of the architecture step, two passages of the verify step, and the whole lane law from "Gates worth remembering" — and a sixth passage, the junior-delegation excess, was appended to the existing `references/delegation-protocol.md`, which grew 8,526 to 10,060 bytes. `guardrails/rule-census.json` records the body's finding total falling 255 to 207 and the delegation file's rising 52 to 58, with a `reason` line that states the provenance honestly. `ARCHITECTURE.md` renumbers six pins. Seven test files change import and call sites only.

## Whether the move is word for word

It is. I read `git show 9efe559:skills/build-pipeline/SKILL.md` and compared it against the five new files and the appended tail of `delegation-protocol.md` with a whitespace-collapsing containment check run under `python3 -c`: every prose block in every new file, and both appended blocks in `delegation-protocol.md`, appears verbatim in the pre-commit body. The only blocks that do not match are the six new one-paragraph file headers, which are new writing and are declared as such.

I then ran the check in the opposite direction, which is the one that catches a silent drop: I took every removed line of `git diff 9efe559 HEAD -- skills/build-pipeline/SKILL.md -U0`, split it into sentences, and looked for each in the union of the new body and all thirteen reference files. Sixty-nine sentences, sixty-seven found. The two misses are both benign and I confirmed each by hand: one is a sentence-splitter artifact on the `crosscut_counter.py` parenthetical, which `grep` finds intact in `references/footprint-read.md`; the other is the old delegation pointer sentence, which was deliberately rewritten to name the cleanup-safety constraint and the per-block root accounting that the same commit moved into that file. So no sentence was lost, altered or reworded. The commit message's central claim survives an adversarial read.

`delegation-protocol.md` is append-only against its 9efe559 form — I checked that the old file is a literal prefix of the new one — and its added material is verbatim body text. But verbatim is not the same as warranted, which is the next section's problem.

## The pointers, and the one that broke

Twelve distinct reference links now stand in `SKILL.md`. I resolved all twelve with `test -f` from the skill root and all twelve exist. As prose they meet skill-creator's bar for a pointer: each names the destination and then says what the reader will find there and when it matters — "for the full read: how the footprint composes with the door, what each footprint grants each step, what a three-source disagreement owes, and the mid-work re-classification" is exactly the shape skill-creator asks for, an inventory rather than a bare "see also". The lane pointer and the verify pointers read the same way. This part of the work is good.

The defect is one directory deeper. `references/lanes-and-pen.md` carries, verbatim from the body, the sentence pointing at the drafter-applier worked run — and that sentence was written as `[references/drafter-applier-example.md](references/drafter-applier-example.md)` when it lived in `SKILL.md`, where the path was correct. From inside `references/` the same string resolves to `references/references/drafter-applier-example.md`, which does not exist. This is the precise hazard of a verbatim move: the text was right where it was and is wrong where it now sits.

The consequence is worse than one dead link. A grep for `drafter-applier-example` across the skill finds it named in exactly one place, that broken link. `SKILL.md` no longer mentions it at all, because its only mention was inside the moved block. So a reference file that existed before this commit and was reachable in one hop is now reachable in none. Nothing in the repository would catch this: I looked for a link-resolution gate under `tests/` and `guardrails/` and there is none.

## Whether this was the right material to move

The lane law is the clear win and should be said first. `references/lanes-and-pen.md` takes 4,862 bytes of procedure — the cap arithmetic, the pen-stage rules, the edge criteria for the dependency graph, the deferred-trigger re-scan, the step-by-step open-lane act — and leaves behind a bullet that still tells a worker the operative shape: up to the profile cap of independent lanes, picked by a graph, each opened as an act performed, with every shared-doc edit and every close taking the pen one lane at a time. A reader who is not opening a lane today can walk past that bullet and lose nothing. That is progressive disclosure done properly.

The worker-restore half of the verify move is also right. The body keeps the whole operative instruction — run `python3 guardrails/check-worker-restore.py` here, read its verdict before accepting the worker's result — and moves only the gate's internals and its red-handling. A worker can execute that step from the body alone.

Three of the cuts went too deep, and they went deep in the same way: each left a rule's name in the body and took its criterion out.

The audit is the most consequential. The body now says the audit is "REQUIRED where the stakes are high and only the author has judged the work" and stops. What "high-stakes" means — surface-sized delta, or an edit to the method itself — and what "the author's own review" means, including the two traps that a prover pass in the author's own context never counts and that delegation never makes a review independent, are now entirely in `references/verify-step-detail.md`. This is the firing condition of a required gate. A worker at step 8 cannot decide whether the audit fires without opening a second file, and the failure mode of not opening it is silent: you conclude the stakes were not high and move on. The pointer does say "what high-stakes means", which is the mitigation, but a required gate's trigger is the last thing that should leave a body.

The three-question fitness test is the same defect, smaller. Step 3 now reads "**Every new or carved node passes a three-question fitness test at its birth (SPEC INV-122):** see [reference] for the three questions". A sentence that names a test and withholds its questions is decorative — it can be read, agreed with, and not performed. The three questions run about thirty-five words. They belonged in the body.

The runtime and placement views are borderline and I will call them a miss rather than a defect. Step 3 now says the doc owes "the **runtime view** and the **placement view**" with no indication of what either contains, which makes the step's deliverable unwritable from the body. What saves it is step 4, which still glosses both in its check list — the runtime view walks every promised flow, the placement view says where every node runs — so a reader who reaches the prover step recovers the gist. It is odd that the proving step now carries more definition of these views than the authoring step that owes them.

`references/mockup-first-entry.md` is the one file I would simply not have made. The moved passage is four lines and roughly 430 bytes; the pointer that replaced it is about 180. The net saving to a 52 KB body is a quarter of a kilobyte, and the cost is a whole file, a broken reading rhythm in an intake bullet list whose every sibling is stated in full, and a reader who must leave the page at step zero to learn what "cancelled only by name" cancels. Progressive disclosure buys nothing when the payload is barely larger than the pointer. The body sentence that remains is at least actionable on its own — honour it from the row, cancel only by name — so this is waste rather than breakage.

The footprint cut sits in between. The body still says a footprint must be named and written in the row's `footprint:` note, which is the duty, but it now offers the three names as bare labels with their one-clause definitions gone. Restoring the three parentheticals — presentation-only touches what the audience meets, single-module stays inside one owned layer, cross-cutting moves a shared law or several layers — costs about thirty words and makes the intake line self-sufficient again, which matters because this decision is taken before any tool call.

## What was appended to delegation-protocol.md, and why it should not have been

The appended section is verbatim body text, as claimed. But `delegation-protocol.md` already stated the brief's three birth laws under INV-53/54/55, the worker contract under ACT-3, the disjointness duty under INV-105, the reporting duty under INV-103 and INV-137, and the per-block root accounting under INV-314 — that is what the old body pointer advertised the file as containing. The appended paragraph restates all six, in the body's shorter words, under a heading that says "as the body stated them". I checked for exact sentence duplication between the file's original part and its appended part and found none, which means the duplication is the worse kind: two paraphrases of one law in one file, with no rule for which one governs when they drift.

Only one clause in the appended block is genuinely new to that file — the cleanup-safety constraint under INV-162, which had no home there before. The honest move was to fold that one clause into the existing worker-contract section and delete the rest. As it stands the file grew 1,534 bytes to gain one clause, and its finding count rose 52 to 58 to carry six restatements.

## What the tests actually do

The commit subject says "the tests read the whole surface". What changed in `tests/` is that six assertions swapped `read`/`read_flat` for the pre-existing `read_all`/`read_all_flat` helpers, which concatenate `SKILL.md` with `references/*.md`. That is an accommodation of the move — it stops assertions failing now that their needles live in a different file — not new coverage of it. I ran `python3 -m pytest -q` over the seven touched test files and got 248 passed, 1 skipped, so the accommodation works.

What is missing is any test that guards this move. Nothing asserts the five new files exist, nothing asserts the body still points at them, nothing asserts the moved text survived, and nothing holds the body at its new length. The pack has the precedent right there: the communicator slimdown shipped `tests/test_communicator_body_thinned.py` and `tests/test_communicator_register_extracted.py`. The largest body cut of the three skills in this range shipped neither. A grep for the five new filenames across `tests/`, `guardrails/` and `scripts/` returns nothing but `rule-census.json`.

I also ran `tests/test_architecture_pins.py`, which passes with 2 tests, and note that it passes despite a pin degradation this commit introduced: `ARCHITECTURE.md` previously pinned "trains, one pen" and "the graph picks the lane set at queue-take" to two distinct paragraphs at `SKILL.md:563` and `:580`, and now points both at `SKILL.md:504`. The graph law no longer lives in the body at all; its home is `references/lanes-and-pen.md`. The same node block already pins `references/delegation-protocol.md:71`, so pinning into a reference file is established convention here and was available. Two facts now share one pin and the deeper of the two is not at the line named.

## Frontmatter, name, description

The frontmatter is well-formed and carries `name`, `description`, and a `metadata.version` of 5.0.0. The extra `metadata` block is outside skill-creator's named set of `name`, `description` and the optional `compatibility`, but it is the pack's consistent convention across skills and is harmless.

The name is a good one — a noun phrase naming the artifact the skill runs, unambiguous against its siblings. The description meets skill-creator's bar and clears it on the point skill-creator worries about most, undertriggering: it enumerates the doors by name (feature, bug fix, behavior change, refactor, docs-only, feature removal), it covers the second entry the skill supports with the actual phrases a person speaks ("attach live-spec to this project", "onboard this codebase"), and it closes with an explicit negative boundary — a tiny reversible edit and pure research stay outside — which is precisely the near-miss discrimination skill-creator asks the should-not-trigger cases to test. None of this commit's changes touch the description, and it needed none.

## Length and shape after the cut

Better, and not yet good. Skill-creator's guidance is under 500 lines with an added layer of hierarchy as you approach that limit; the body went 672 to 559, so the direction is right and the added layer is exactly the mechanism skill-creator prescribes. It still overshoots by about sixty lines, and the remaining bulk is not where this commit looked: step 9 alone is a single unbroken paragraph of roughly two thousand characters covering push, README re-walk, CI verdict read, version bump and tier judgment, which the census records as the file's longest line at 198 words. That paragraph is the next honest cut, and it is a better candidate than the mockup-first bullet was.

On navigability the verdict is mixed. The intake section and the gates section read faster and lose nothing a reader needs at a glance. The architecture and verify steps read worse: each now has the rhythm of a step that announces obligations and defers their content, and a worker walking the pipeline top to bottom hits three "see reference" hops inside step 3 alone, all three to the same file. If those three passages must live outside the body, the pointer should be one consolidated hop at the head of the step rather than three interruptions to the same destination.

## The net

The moved bytes are honest and the pointers from the body are well written, so the core of what this commit claims stands up. Four things need repair before this is finished. The link inside `references/lanes-and-pen.md` must be re-based to `drafter-applier-example.md` so that file stops being orphaned. The audit's high-stakes definition and the fitness test's three questions should come back into the body, since both are firing conditions rather than elaboration. The appended section of `delegation-protocol.md` should shrink to the one clause it actually added. And this move deserves the test the communicator move got — one that reads the pointer, resolves it, and holds the body's length — because right now nothing in the repository would notice if a pointer went stale, and this commit shipped proof of that.
