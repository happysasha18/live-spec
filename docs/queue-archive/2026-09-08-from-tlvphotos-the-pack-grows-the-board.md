# The pack's own wording grows the board

From: the tlvphotos seat, 2026-09-08. This is a case, with the incident that produced it.

## What happened

A session repaired the crossing arsenal across a long day. It opened no new row, and it still
produced a backlog it was about to hand to the next session. The owner caught it and said the rule
plainly: «нельзя плодить таски… ты закрываешь все что знаешь сейчас в этой сессии и далее задачи
откроются только в результате этого художественного ревью.»

The seat then looked for where the habit came from and found two places in the pack's own wording,
rather than in the session's judgement alone.

## Defect one: a document with a queue section gets a queue written into it

`NEXT_STEPS.md` is described as carrying "the live state and the forward queue". A resume file that
declares a queue section invites every session to fill it, and what lands there is work nobody
admitted to the board and nobody scheduled. The board then competes with a second list that has no
acceptance command, no status and no owner.

The project already has one queue, and it is the board. A resume file records what happened and
where the work stands.

Suggested repair: describe the resume file as the live state only. Where a session believes
something is owed, it either closes it before ending or the owner opens a row for it in his own
words.

## Defect two: the specialists hand findings onward, so a brief splits diagnosis from repair

`design-reviewer` holds no landing and every finding is a recommendation or a question. That shape
is right for a reviewer. What it teaches by example is a brief of the form "find the cause and name
the repair, do not build it", and the seat wrote several of those in one day. Each one manufactured
a handoff, and a handoff becomes a row.

The measured effect in this session: four separate diagnoses came back naming repairs, and each
would have become a row had the owner not stopped it.

Suggested repair: state, wherever the pack briefs a lane, that whoever finds a cause fixes it in the
same lane. Name the reviewer's no-landing rule as the one deliberate exception, and say why it is an
exception, so it stops reading as the general pattern.

## What the seat is not claiming

Neither defect is the whole cause. The seat's own briefs did the splitting, and a rule in a document
would not have written them differently on its own. What the wording did was make the split look
like the pack's own shape, so nothing in the session flagged it.

## Related, already recorded

The same session found two more standing laws in the owner's words, both project-side rather than
pack-side, recorded here only so the pack's authors can see the register they arrive in:

- a criterion says what must be true and never states a measurement procedure; a recorded pixel run
  proves only the machine that recorded it, so it never stands as a criterion's evidence;
- once a work has left a crossing it never comes back.
