## Requirements — one line each, quoted, with who it reaches

1. **The fence itself.** "Re-check `git status` and HEAD against what you last read. If HEAD moved, or the tree holds changes you did not make, stop, re-read, then proceed surgically or back off. A repo you were not assigned to is read-only (one exception: a new wish file in its inbox)." (`SKILL.md:170-172`) — reaches every skill that writes shared files, adoption among them (the rule's own words, SPEC INV-10, INV-11); mechanically enforced by `guardrails/pre-commit` (opt-in via `guardrails/fence-refresh.sh`) and re-armed by `guardrails/post-commit`.

2. **Lanes under one pen, up to the profile cap.** "Within one session, build lanes up to the profile-declared lane cap may roll without asking (SPEC T-18; `lanes.cap`, package default three [E-13]; one more only on the human's asked word). Every write to a document the lanes share serializes under the single PEN." (`SKILL.md:175-178`) — reaches the orchestrating session running parallel build lanes, and the project's own `lanes.cap` profile setting.

3. **The lane-open act.** "Opening a lane is a step the session performs, by running `scripts/open-lane.sh` or by walking the same steps by hand... First, the row→in-work flip is committed to main under the pen. Second, the branch `lane/<row>-<slug>` is cut from that claim commit into its own worktree. Third, the lane is handed to a worker whose brief names the branch." (`SKILL.md:181-185`) — reaches the session opening a lane; performed mechanically by `scripts/open-lane.sh` (SPEC INV-214).

4. **Worktree isolation on overlap.** "A later lane's code and tests live in its own isolated copy of the tree until the senior integrates them... a shared file one lane holds open is never written by another (SPEC INV-105)." (`SKILL.md:190-192`) — reaches any lane whose write-set overlaps another lane's, and the senior/orchestrating session that integrates them.

5. **Brief-time disjointness.** "before spawning another concurrent writer, the senior confirms its brief's write-set is disjoint from every already-running writer's brief, or gives it an isolated worktree at brief-time. The fence stays silent between same-session siblings and cannot catch the senior's own workers colliding (SPEC ACT-3, INV-11)." (`SKILL.md:193-196`) — reaches the senior/orchestrating session, at the exact moment it briefs a new concurrent writer.

6. **A worker never restores a working tree with a git command.** "Before a worker mutates a file it means to put back, it reads that file and holds its bytes. A worker puts a file back by WRITING ITS OWN SAVED BYTES. A worker runs no command that discards uncommitted work, in any tree: `git checkout -- <path>`, `git checkout .`, `git restore` outside `--staged`, `git stash`... `git reset` with `--hard`, `--merge` or `--keep`, and `git clean` with `-f` or `-x`." (`SKILL.md:197`, SPEC INV-298) — reaches every worker in every tree, including its own isolated worktree; mechanically enforced by `guardrails/check-worker-restore.py`, pinned by `tests/test_worker_restore.py`; the orchestrator's own half ("A finished build stage is committed before the next worker touches its files") reaches the orchestrating session.

7. **One row per landing commit.** "A landing commit carries exactly one row's delta, its gate run on a tree clean of any other lane's unfinished work (SPEC INV-39)." (`SKILL.md:198`) — reaches the session committing a landing.

8. **A prior-context worker is a concurrent writer too.** "A background worker from a prior context is a concurrent writer too. It survives a memory wipe, and the process list and the harness task panel are never proof of death... No second worker goes onto a shared tree until the first has confirmed halted by its own reply, or been declared dead by all three checks." (`SKILL.md:199-204`, SPEC INV-76) — reaches any session about to spawn a new worker onto a tree a prior worker from an earlier context might still hold; ties to rule 6's three resume checks.

9. **A stable session identity breaks the pen tie.** "Every session mints a stable identity at its start and records it in its `.live-spec/` checkpoint, unchanged for the session's life... The parallel-lanes pen tie-break orders on this identity for a genuine concurrent claim with no git ancestry, so exactly one session backs off (SPEC INV-117)." (`SKILL.md:205-210`) — reaches two sessions racing to claim the same pen with no git ancestry between their claims.
